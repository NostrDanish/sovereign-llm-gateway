# Security Audit — sovereign-llm-gateway — 2026-10-20

## Summary
Single-file JS experiment (gateway.js, read in full): subscribes to NIP-17 gift-wrapped DMs (kind 1059) and pipes the decrypted content into a local LLM (`ollama run llama3.2`) via `execFile`, then gift-wraps the reply. No secrets committed. Findings: 0C / 0H / 1M / 2L.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| M1 | MEDIUM | gateway.js | **Unauthenticated execution surface**: anyone who learns the gateway pubkey can DM it and trigger local LLM inference (cost/abuse) and prompt-injection against the local model; replies are auto-published, so injected content can be exfiltrated/broadcast under the gateway identity. `execFile` (no shell) correctly avoids shell command injection — that part is good. | Maintain a pubkey allowlist of authorized requesters; rate-limit; treat model output as untrusted before publishing. |
| L1 | LOW | gateway.js | No explicit NDK signer configured (key source implicit); decrypted DM content logged to stdout (`console.log` first 80 chars) — privacy note. | Wire signer from env explicitly; avoid logging DM content. |
| L2 | LOW | repo-wide | No package.json/lockfile; no SECURITY.md. | Add manifest with pinned deps; add SECURITY.md. |

## Secrets Check
gateway.js read in full — only public relay URLs; no API keys (local ollama, no OpenAI/xAI usage). Org-wide searches for `nsec1`, `sk-`, `xai-`, `nostr+walletconnect://`, `PRIVATE KEY` — **no secrets found**.
